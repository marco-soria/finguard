## Goal
Before the API gets a public URL: every endpoint lives under `/api/v1/...`; the API publishes an OpenAPI 3.1
document generated by ASP.NET Core and rendered with Scalar; the submission history is paged with a cursor and
filterable by status, cut-off date range and "current only", with a "Load more" button in the SPA. The OpenAPI
document is pinned by a snapshot test so every contract change shows up in a PR.

  `.claude/rules/frontend.md`, `.claude/rules/testing.md`, `docs/decisions.md` (newest delta: session 30, Brief #19

- `ListSubmissionsHandler` returns at most 100 rows (`Max`, D-100), newest first, `isCurrent` derived in SQL (D-141).
  Indexes on `portfolio.submissions`: `(tenant_id, cut_off_date, received_at)` and `(tenant_id, cut_off_date, sha256)`;
  none matches the list's `ORDER BY received_at DESC, id DESC`.
- Package facts checked on 2026-11-27 (re-verify in preflight and report exact versions; stable only):
  - `Microsoft.AspNetCore.OpenApi` 10.0.x is the first-party generator; .NET 10 generates OpenAPI 3.1 by default.
  - `Scalar.AspNetCore` 2.x renders the document with `app.MapScalarApiReference()` (UI at `/scalar`). It ships
    frequent patch releases; pin an exact version in `Directory.Packages.props`.
  - Microsoft docs show both Swagger UI and Scalar over the built-in document; Swashbuckle is not used.

## Decisions taken for this brief (Appendix A has the full delta)
| Topic | Decision | Rejected |
| --- | --- | --- |
| API versioning | URL segment by convention: every module group maps under `/api/v1/<module>`, from one constant in BuildingBlocks (`ApiRoutes.V1`). Contract changes stay additive (same rule as ADR-0011 for events); a breaking change would add `/api/v2` and the `Asp.Versioning.Http` library at that moment. Response header and deprecation policies arrive with v2, not before | `Asp.Versioning.Http` now (the only client is our SPA, released together; one version is overhead today); no prefix (moving every route later, after it is public, costs more than now) |
| OpenAPI | `Microsoft.AspNetCore.OpenApi`, one document `v1`, OpenAPI 3.1. Document transformer adds the Bearer security scheme and API title/description. Every endpoint declares name, summary, tag (module), success type and `ProducesProblem` codes. `/dev/token` is tagged `Development` and only exists in Development | Swashbuckle (no longer the template default) |
| UI for the docs | Scalar at `/scalar`, document at `/openapi/v1.json`. Mapped when `Api:Docs:Enabled` is true: default true in Development, false elsewhere; Phase 5 decides whether to expose it publicly | Swagger UI (older look, fewer features; both work) |
| Contract pinning | Integration test fetches `/openapi/v1.json` from `ApiFixture` and compares it with `docs/api/openapi.v1.json` (committed, normalised JSON). A mismatch fails with a hint: run the update script `scripts/update-openapi-snapshot.ps1` and commit | Build-time generation (starts the app at build time; Wolverine and database configuration make it brittle) |
| Paging | Keyset cursor. `GET /api/v1/portfolio/submissions?limit=&cursor=` → `{ items, nextCursor }`. `limit` default 25, max 100. Cursor = opaque base64url of `(receivedAt, id)` of the last item; invalid or tampered cursor → 400 ProblemDetails (`Portfolio.Submissions.InvalidCursor`). `nextCursor` null on the last page | Offset paging (unstable while new uploads arrive); total counts (an extra query nobody needs) |
| Filtering | `status` (`Accepted` / `Rejected`), `cutOffFrom`, `cutOffTo` (inclusive, ISO dates, from ≤ to), `currentOnly` (bool). All optional, validated, combined with AND. `isCurrent` is still computed over all of the tenant's submissions, never over the filtered page | Free-text search on file name (low value; add `ILIKE` later if asked) |
| Sorting | Fixed: `receivedAt` desc, `id` desc. No sort parameter | Client-chosen sort (complicates the cursor for little value) |
| Index | New index `(tenant_id, received_at DESC, id DESC)` on `portfolio.submissions`; verify with `EXPLAIN` that the list query uses it | |
| SPA | History page: filter bar (status select, from/to dates, "Current only" toggle), filters kept in the URL query string, "Load more" button appending pages, empty state per filter. API paths come from one base constant | Infinite scroll (harder to test and to use with a keyboard) |
| How to change a limit | README section "Changing a limit": add a policy version in a migration with an effective date (D-300); old evaluations keep their version | |

## Tasks

### 1. v1 routes
- `ApiRoutes.V1 = "/api/v1"` in BuildingBlocks; every module group uses it. `/health`, `/alive`, `/dev/token`,
  `/openapi/*`, `/scalar/*` stay outside.
- SPA: one `API_BASE = '/api/v1'` constant used by every `*-api.ts`; interceptor and proxy keep matching `/api/`.
- Architecture or integration test: every mapped endpoint except the allow-list starts with `/api/v1/`.

### 2. OpenAPI and Scalar
- Register the generator and the transformer; endpoint metadata on every route; `Api:Docs:Enabled` option.
- Snapshot file, normalising update script, snapshot test.

### 3. Submission history paging and filters
- Request validation (Result pattern, 400 with field errors), cursor encode/decode helper with tests, Dapper query
  with keyset predicate `(received_at, id) < (@ts, @id)` and filters, `isCurrent` CTE unchanged in meaning.
- Migration for the index; `has-pending-model-changes` clean.
- Response contract change (list → envelope) is breaking for the list endpoint only; the SPA is updated in the same
  PR (the only client).

### 4. SPA history page
- Filter bar, URL state, "Load more", empty states; Material components; accessible labels.

### 5. Docs
- `README.md`: API documentation link (`/scalar` in Development), "Changing a limit" section, updated "Try it" paths.
- `.claude/rules/backend-vsa.md` + `.cursor/rules/backend-vsa.mdc` (same commit): routes under `ApiRoutes.V1`; every
  endpoint declares OpenAPI metadata; update the snapshot when the contract changes; additive changes only.
- `docs/architecture/overview.md` if it lists routes; `docs/decisions.md`: Appendix A, then the execution delta.

## Tests that prove it
Unit: cursor round-trip, tampered and malformed cursors rejected; filter validation (from > to, unknown status,
limit 0 / 101); route prefix constant.
Architecture / integration: route allow-list test; OpenAPI snapshot test; the document contains the Bearer scheme and
every `/api/v1` operation has a summary and at least one problem response.
Integration (real PostgreSQL, through HTTP):
- `List_PagesThroughAllSubmissions_WithoutGapsOrDuplicates` (seed 60, limit 25 → 25/25/10, next cursor null at end).
- `List_NewUploadBetweenPages_DoesNotShiftLaterPages`.
- `List_FilterByStatus`, `List_FilterByCutOffRange`, `List_CurrentOnly_ReturnsOnlyCurrentVersions`,
  `List_FiltersCombine`.
- `List_IsCurrentComputedOverAllSubmissions_NotThePage`.
- `List_InvalidCursor_Returns400`, `List_OtherTenantsCursor_ReturnsNoForeignRows` (cursor from tenant A used by B).
- `OpenApi_DisabledOutsideDevelopment_Returns404` and enabled in Development.
- Existing endpoint tests pass on `/api/v1` paths.
Vitest: API base constant; history filters ↔ URL; "Load more" appends and hides at the end; empty states.
E2E: history filter by status and "Load more" with enough uploads (create them through the API in the test setup);
existing tests on the new paths. Run twice.

## Rules to respect
- ADR-0007: Dapper read with the mandatory `tenant_id` filter; the cursor never bypasses it.
- No financial values or dates in logs. The OpenAPI document contains no secrets or sample data from real tenants.
- Additive API changes from now on; the list envelope is the one planned exception, done before the API is public.

## Out of scope
Rate limiting, forwarded headers, `xmin` (#21); `Asp.Versioning`; TypeScript client generation from OpenAPI;
free-text search; paging on other endpoints (none return lists); Phase 5 exposure of `/scalar`.
