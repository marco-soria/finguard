## Goal
Create the .NET solution and every backend project as an empty but running modular monolith: `aspire run` starts
PostgreSQL and the Api; the Api connects to the database through one `NpgsqlDataSource`, one DbContext per module (own
schema, own migrations history table), Wolverine with durable message storage in the `wolverine` schema, OpenTelemetry to
the Aspire dashboard, health checks, cloud seams, `Result`/`Error` types and a global ProblemDetails exception handler.
No business logic, no tables, no endpoints beyond health.

### 5. BuildingBlocks: Result, Error, HTTP mapping, DbContext options
- `Results/ErrorType.cs`: `Validation`, `NotFound`, `Conflict`, `BusinessRule`.
- `Results/Error.cs`: `sealed record Error(string Code, string Description, ErrorType Type)` with factory methods
  (`Error.Validation(code, description)`, etc.). Codes look like `Portfolio.Submission.NotFound`.
- `Results/Result.cs`: `Result` (`IsSuccess`, `IsFailure`, `Error`, `Success()`, `Failure(Error)`) and `Result<T>`
  (`Value` throws `InvalidOperationException` when accessed on a failure; implicit conversions from `T` and from `Error`).
  No exceptions for expected failures anywhere.
- `Http/ResultHttpExtensions.cs`: `ToHttpResult(this Result)` (success: 204) and
  `ToHttpResult<T>(this Result<T>, Func<T, IResult> onSuccess)`. Failure mapping, all as RFC 9457 ProblemDetails with
  an extension `code`: `Validation` 400, `NotFound` 404, `Conflict` 409, `BusinessRule` 422.
- `Persistence/ModuleDbContextOptions.cs`: one extension that every module uses for runtime and design time, so both
  paths configure EF identically:
  ```csharp
  public static DbContextOptionsBuilder UseModuleNpgsql(
      this DbContextOptionsBuilder options, string connectionString, string schema) =>
      options
          .UseNpgsql(connectionString, npgsql => npgsql.MigrationsHistoryTable("__ef_migrations_history", schema))
          .UseSnakeCaseNamingConvention();
  ```
  Never call `EnableSensitiveDataLogging` and never enable Npgsql parameter logging.
- BuildingBlocks contains no business rules (ADR-0001).

### 7. Api composition root (`Program.cs`)
In this order:
1. `builder.AddServiceDefaults();`
2. `builder.Services.AddSingleton(TimeProvider.System);`
3. `builder.AddNpgsqlDataSource("finguard");` (Aspire.Npgsql; the data source health check covers the database).
4. Module registration: `builder.AddTenancyModule(); builder.AddPortfolioModule(); builder.AddComplianceModule();
   builder.AddAdvisoryModule();`. Each `AddXxxModule` registers its DbContext with
   `AddDbContext<XxxDbContext>(o => o.UseModuleNpgsql(connectionString, XxxDbContext.Schema))`, where
   `connectionString` comes from `builder.Configuration.GetConnectionString("finguard")` (fail fast with a clear message
   when it is missing), then calls `builder.EnrichNpgsqlDbContext<XxxDbContext>(s => s.DisableHealthChecks = true)`.
5. Wolverine:
   ```csharp
   builder.Host.UseWolverine(opts =>
   {
       opts.PersistMessagesWithPostgresqlUsingDataSourceFromContainer(schemaName: "wolverine");
       opts.Discovery.IncludeAssembly(typeof(TenancyModule).Assembly);   // and the other three modules
       // Development may use opts.Durability.Mode = DurabilityMode.Solo
   });
   ```
   Reference `WolverineFx`, `WolverineFx.Postgresql`, `WolverineFx.RuntimeCompilation` (and call whatever opt-in the
   6.x docs require for runtime compilation). Do NOT call `UseEntityFrameworkCoreTransactions`,
   `AddDbContextWithWolverineIntegration`, `UseEntityFrameworkCoreWolverineManagedMigrations`, `RestoreV5Defaults` or
   any option that clears envelope storage on startup. Message storage tables must be created automatically on startup;
   if the 6.x default does not do it, use the documented auto-create setting and report which one.
6. Dapper: `Dapper.DefaultTypeMap.MatchNamesWithUnderscores = true;` once, at startup.
7. Errors: `builder.Services.AddProblemDetails(...)` adding a `traceId` extension (`Activity.Current?.Id` or
   `HttpContext.TraceIdentifier`); `builder.Services.AddExceptionHandler<GlobalExceptionHandler>();`
   `GlobalExceptionHandler : IExceptionHandler` logs with a message template (exception type and trace id only), and
   writes a 500 ProblemDetails with a generic title, no detail, no stack trace, no exception message, in every environment.
8. After `Build()`: `app.UseExceptionHandler(); app.UseStatusCodePages();`, then
   `if (app.Environment.IsDevelopment()) await app.ApplyModuleMigrationsAsync();` (an extension in the Api that runs
   `Database.MigrateAsync` for the four DbContexts in a scope, logging one line per module), then `app.MapDefaultEndpoints();`
   and the four `MapXxxEndpoints()` calls.
9. `appsettings.json`: logging levels only. No connection strings, no `KeyVault:Uri`.
